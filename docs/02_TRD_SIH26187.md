## Section 2: Architecture Component Specifications

### 2.1 Model A — Module Creator (Lightweight Filter/Classifier)

- **Purpose:** Gatekeeper — ingests raw frames, filters redundancy, tags zones, detects absolute triggers, normalizes output into a unified JSON schema.
    
- **Input:** Raw RTSP frames from multiple IP CCTV cameras (H.264/H.265).
    
- **Output:** (a) Training dataset for Model B engines; (b) Real-time flagged modules + metadata JSON.
    
- **Functions:**
    
    - _Time-sampling:_ Skip redundant/identical frames using frame-difference threshold (e.g., MSE < 0.001 = skip).
        
    - _Most-differentiated-frame selection:_ Within a sampling window, select frame with maximum inter-frame variance.
        
    - _Range/zone tagging:_ Classify frame as Close Range (<=15m) or Long Range (>15m) based on object size and camera calibration.
        
    - _Absolute-trigger detection:_ Climbing, fence-cutting, rapid motion toward fence. **Must persist across 2-3 consecutive frames before flagging** (hard requirement to fix 50 false alerts/night CIBMS failure).
        
    - _Normalization:_ Both motion and trigger events output into one JSON event schema.
        
    - _Anti-spoofing check:_ Verify temporal continuity between frames; flag gaps >2s as possible replay/injection.
        
- **Performance Target:** <50ms per frame on Jetson Orin Nano. Memory footprint <2GB.
    

### 2.2 Model B — Engine Suite (4 Specialized Engines)

**2.2.1 Face Engine**

- **Input:** Close-range frames tagged by Model A + detected face bounding boxes.
    
- **Processing:** InsightFace (RetinaFace) → ArcFace embedding extraction (512-dim) → cosine similarity match against watchlist (SQLite/Vector DB).
    
- **Output:** JSON event with `face_id`, embedding vector, confidence, cropped face image path, match score.
    
- **Scope:** Close-range cameras only. Long-range face ID explicitly out of scope.
    
- **Target:** <100ms per face detection.
    

**2.2.2 ANPR Engine**

- **Input:** Close-range frames with vehicle detections (chokepoint/ICP cameras ONLY).
    
- **Processing:** YOLOv8 plate detector → perspective correction (homography transform) → PaddleOCR/CRNN → post-processing (format validation, state code lookup).
    
- **Output:** JSON event with `plate_text`, confidence, `plate_image_path`, `vehicle_bbox`, `camera_id`, timestamp.
    
- **Scope Limitation:** High-mounted BOP cameras explicitly excluded — physics prevents reliable plate reading.
    
- **Target:** <150ms per plate read.
    

**2.2.3 Posture Engine**

- **Input:** All frames with human detections (both close and long range).
    
- **Processing:** MediaPipe Pose → 33 landmark extraction → posture classifier (rule-based or MLP: standing, walking, running, crouching, crawling, carrying).
    
- **Output:** JSON event with `posture_class`, confidence, landmark snapshot, `anomaly_score`.
    
- **Target:** <80ms per person.
    

**2.2.4 Trajectory Engine**

- **Input:** All frames with human/vehicle detections + track IDs from ByteTrack/DeepSORT.
    
- **Processing:** Kalman filter + Hungarian algorithm → trajectory smoothing → velocity/direction → zone transition detection → behavior pattern analysis.
    
- **Output:** JSON event with `track_id`, `trajectory_points`, velocity, direction, `zone_transitions`, `behavior_tags`, confidence.
    
- **Target:** <50ms per track update.
    

### 2.3 Event Bus & Orchestrator

**Unified Single-Line Bus**

- **Pattern:** MQTT Publish-Subscribe. Every engine publishes independently.
    
- **Security Decision (Locked):** Absolute triggers do NOT get a bypass channel (prevents unmonitored spoofing). Triggers are tagged CRITICAL severity on the SAME validated bus.
    
- **Topics:** Fixed naming convention (e.g., `sih26187/camera/{cam_id}/model_a/raw`).
    
- **QoS & Retention:** QoS 1 for standard events (7 days retention), QoS 2 for critical alerts (90 days). Indefinite for evidence-linked events.
    

**Orchestrator (Context-Reasoning Layer)**

- **Input:** All events from unified bus.
    
- **Functions:**
    
    - _Threat scoring:_ Combine posture + zone + time + trajectory into composite threat score (0-100).
        
    - _Border Context Profile:_ Adjust thresholds/weighting per deployment (BSF/SSB/ITBP).
        
    - _Package-drop detection (PROPOSED):_ Object separates from person-track and stays static for >30s.
        
    - _Group-coordination detection (PROPOSED):_ 3+ tracked entities, same zone, same direction, within 60s.
        
    - _Alert & Evidence:_ Publish to dashboard if score > threshold. Bundle JSON + media + hash manifest for forensics.
        
- **Target:** <100ms per event batch processing.
    

### 2.4 Locked JSON Event Schema

_Must be frozen before parallel engine development starts. Retrofitting later into 5 engines is expensive._ **Versioning Strategy:** If schema needs to grow, version it (`schema_v1`, `schema_v2`) rather than mutating fields in place to prevent breaking engines.

JSON

```
{
  "event_id": "string (UUID v4)",
  "event_type": "enum [motion, trigger, face_detected, plate_read, posture_anomaly, trajectory_update, zone_transition, system_health, camera_anomaly]",
  "severity": "enum [info, warning, critical, emergency] (also provisional or confirmed)",
  "timestamp": "string (ISO 8601 UTC)",
  "camera_id": "string",
  "zone_tag": "enum [close_range, long_range, warning_zone, intrusion_zone, chokepoint, icp, perimeter]",
  "entity_type": "enum [human, vehicle, animal, animal_cart, unknown]",
  "engine_source": "enum [model_a, face, anpr, posture, trajectory]",
  "entity_id": "string (track_id or face_id or plate_text or null)",
  "confidence": "float (0.0-1.0)",
  "bbox": "[x1, y1, x2, y2] (normalized 0-1)",
  "evidence_ref": "string (filepath or URL to image/video snippet)",
  "metadata": {
    "model_version": "string",
    "engine_name": "string",
    "processing_time_ms": "int",
    "frame_number": "int",
    "additional": "object (engine-specific extras)"
  },
  "hash": "string (SHA-256 of evidence_ref file for tamper-detection)",
  "provisional": "boolean (true if Model A trigger awaiting Model B confirmation)"
}
```

## Section 3: Hardware Requirements

- **Primary Target (Production):** NVIDIA Jetson Orin Nano (8GB) — ~$249. Target <30W total power draw.
    
- **Demo Hardware (Hackathon):** Any local RTX-class gaming laptop capable of near-real-time YOLOv8 + MediaPipe + ArcFace inference. Frame Jetson as "production target", demo runs on dev hardware.
    
- **Demo Contingency:** If no dedicated GPU is available, use smaller YOLOv8n at reduced resolution, or use pre-recorded inference output looped (disclosed honestly).
    
- **Alternative Edge Nodes:** Raspberry Pi 4 + Coral USB TPU (~$150, higher latency) OR Intel NUC i3 + eGPU (~$600, higher power).
    
- **Storage:** 256GB NVMe SSD (holds 7 days of continuous evidence at 4 cameras × 1080p @ 2Mbps).
    

## Section 4: API Contracts

- **Model A → Event Bus:** POST equivalent to MQTT `sih26187/camera/{cam_id}/model_a/raw` with JSON schema.
    
- **Model B Engines → Event Bus:** Publish to respective topics with identical schema.
    
- **Orchestrator → Dashboard:** WebSocket push on `sih26187/dashboard/events`.
    
- **Dashboard → Orchestrator (REST API base `/api/v1/`):**
    
    - `POST /alerts/{event_id}/ack` — acknowledge alert
        
    - `POST /alerts/{event_id}/escalate` — escalate to higher command
        
    - `GET /cameras` — list all cameras with health status
        
    - `POST /cameras/{cam_id}/ptz` — PTZ control
        
    - `GET /events` — query events with filters
        
    - `GET /evidence/{event_id}` — download evidence package
        
    - `GET /health` — system health summary
        
    - `POST /profiles/{profile_id}/activate` — switch Context Profile
        

## Section 5: Fallback Logic & Pipeline Continuity (Locked)

If any Model B engine fails (crash, timeout, memory exhaustion, model load failure):

1. Health monitor detects failure via heartbeat timeout (>30s no publish).
    
2. Orchestrator tags engine as DEGRADED.
    
3. That camera's traffic routes back through Model A's basic motion+trigger detection (Safety Floor).
    
4. Model A continues publishing at reduced capability (no face/ANPR/posture/trajectory).
    
5. Dashboard shows FALLBACK ACTIVE indicator for affected camera.
    
6. No automatic restart — manual intervention or scheduled restart only (prevents restart loops).
    

_Important: Model A cannot replace Model B; it solely prevents total blindness during an outage._

## Section 6: Security & Data Integrity

- **Evidence Integrity:** Every event carries a SHA-256 hash of the evidence file + model version + timestamp. Evidence package includes `manifest.json` with digital signatures.
    
- **Anti-Spoofing/Replay Detection:** Footage lacking trajectory/posture/temporal continuity gets flagged inside Model A (checks timestamp monotonicity and FPS consistency).
    
- **Camera Health Monitor:** Detects lens obstruction, darkness, frozen stream, FPS anomalies.
    
- **Camera-Link Security (Proposed):** Zero Trust segmentation, mutual authentication (TLS/pre-shared keys), no default credentials, SRT AES-128/256 encryption.
    

## Section 7: Build Order & Agentic Tooling Constraints

**Agent-Assisted ("Wipe Coding") Strategy:** Use your agentic IDE to scaffold each engine as an isolated FastAPI microservice against the locked JSON schema. This allows Model A and Model B engines to be generated in parallel without cross-contamination. _Constraint:_ Freeze topic-naming conventions manually first, and feed it as a rule to every prompt to prevent agent drift.

**Build Dependency Map:**

1. **JSON Event Schema** — _Dependency for everything._
    
2. **Model A** — Shared infrastructure for Virtual Fence and Alerting.
    
3. **Trajectory Engine** — Highest-leverage component (powers tracking, vehicle detection, behaviors).
    
4. **Posture Engine + Border Context Profile** — Tightly coupled.
    
5. **Face Engine + ANPR Engine** — Parallelizable on separate tracks.
    
6. **Orchestrator** — Build after engines produce test events.
    
7. **Dashboard** — Final integration layer.
